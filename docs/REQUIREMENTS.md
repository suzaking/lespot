# LeSpot 要件定義 v1.0

基準日：2026-10-11。サービス方針はユーザー指定、数値目標・実現方式は `DECISIONS.md` の暫定推奨。実装・実データ確認・公開は未実施。

## 1. 結果と完成の定義

### 1.1 この設計作業の成功条件

MVPの境界、機能・非機能要件、画面、データ、API、運用、試験、依存関係付き実装タスクが整合し、次のエージェントが正本から作業を開始できること。設計書が `main` にCommitされ、反映内容を再取得して検証できていること。設計作成完了はユーザー承認・アプリ完成を意味しない。

### 1.2 製品の目的

外出中に休憩場所を探す際、施設種別ごとに検索し、写真や口コミから座れるか、料金がかかるか、電源があるかを推測する負担を減らす。「近くで自分の条件に合う休憩候補を見つけ、利用条件を確認し、そこへ向かう」までを一つの導線にする。

提供価値は、無料・有料を横断した比較、休憩場所単位の設備・制約、確認済み情報と不明情報の可視化。空席、安全、利用権、実際の営業を保証するサービスではない。施設名検索や経路探索そのものを独自に作り直さない。

## 2. ユーザーと利用シナリオ

以下は検証前の仮説であり、実在の調査対象者ではない。

| ペルソナ | 状況・課題 | 達成したいこと |
| --- | --- | --- |
| 外出業務の会社員 | 次の予定まで30分、充電したい | 近い屋内・電源ありを比較して選ぶ |
| 買い物・散策中の人 | 疲れたので、追加出費せず座りたい | 無料の休憩スペースと利用条件を知る |
| 長時間移動の人 | 夜間に休憩・仮眠したい | 深夜営業、横臥・仮眠の許可、料金を確認する |
| 事前に予定を立てる人 | PCから同行者の休憩先を調べたい | 現在地許可なしで対象地域と詳細を閲覧する |

UC-01：開始 → 現在地の利用を選択 → 条件を適用 → 近い順一覧 → 詳細 → 外部経路案内。

UC-02：位置情報拒否・地下で精度不足 → 栄等のプリセットまたは地図中心を選択 → 同じ検索導線。

UC-03：無料・屋内等で0件 → 条件ごとの解除候補を表示 → 本人が解除 → 再検索。勝手に有料・不明情報を混ぜない。

UC-04：詳細URLを直接開く → 所在・料金・営業時間・根拠を読む → 必要時だけ位置情報を利用する。

UC-05：運営者が公式情報・現地調査を基に登録 → 検証・差分確認 → 公開 → 再取得確認。一般ユーザーからの書き込みはない。

## 3. 対象地域・掲載単位

初期地域は名古屋市の栄・久屋大通・矢場町周辺。行政上の境界とは別に運営上のカバレッジを設定する。正確な範囲・プリセット座標は現地データ整備時に確認し、設定データとして管理する。全国のデータ取得をMVPの前提にしない。

1スポットは「同じ位置・利用条件・設備で利用できる休憩区画」。同じ商業施設の無料休憩席と有料カフェは別スポットとする。同じ公園内の隣接ベンチは同じ条件の一群としてまとめてもよいが、入口・アクセスが違う区画は分ける。

掲載カテゴリは公園、ベンチ、公共施設、図書館、駅待合、商業施設休憩、地下街休憩、フードコート、カフェ・喫茶店、ファストフード、ファミレス、ネット・漫画喫茶、コワーキング、温浴・サウナ、仮眠施設、カプセルホテル、ホテルデイユース。カテゴリ対応と初期実データの存在は別。根拠のないカテゴリ穴埋めをしない。

## 5. 機能要件と受け入れ条件

すべてMVP必須。標準条件は同項目内OR・項目間AND。定義の詳細は `DETAILED_DESIGN.md`。

| ID | 要件 | 受け入れ条件 |
| --- | --- | --- |
| FR-01 | 任意の現在地取得 | 明示操作でのみ権限要求。許可・拒否・取得失敗・タイムアウト・非対応を区別し、拒否後も閲覧可能。無断で連続追跡しない |
| FR-02 | 現在地を使わない検索 | 栄・久屋大通・矢場町のプリセットと地図中心を選べる。距離基準を「現在地」等のラベルで明示 |
| FR-03 | 地図と一覧 | 同じフィルター結果を地図と一覧へ反映。ピンとカードを相互選択できる。地図失敗でも一覧・詳細が使える。出典を隠さない |
| FR-04 | 距離検索・近い順 | 300/500/1000/2000/3000m、初期1000m。直線距離で安定ソート。徒歩距離・徒歩分数と誤表示しない |
| FR-05 | 条件検索 | 料金区分・最低利用料金、カテゴリ、屋内外、営業時間、滞在時間、座席、各設備、仮眠・横臥、深夜・24時間、静かさ、写真有無で絞れる |
| FR-06 | フィルターの厳密性 | 不明・期限切れ・異議ありを「あり」と一致させない。「条件付きも含む」は明示選択、条件を結果に表示。0件で条件を自動緩和しない |
| FR-07 | 詳細表示 | URLで直接到達でき、名称、場所、階・入口、利用条件、設備、料金、営業時間、出典・確認日を確認できる。戻る操作で検索状態を復元 |
| FR-08 | 料金の正確な表示 | 0円と不明を区別。予算フィルターは「一般成人・予約なし・税込の最低利用料金」であり、滞在総額ではないことを表示。変動・条件付き料金は厳密予算検索から除外 |
| FR-09 | 営業時間と滞在 | 通常営業時間、日またぎ、祝日、臨時休業を区別。「営業時間上は利用可能」と表示し、空席・臨時変更を保証しない。滞在制限不明を無制限としない |
| FR-10 | 写真 | 権利確認済みの実施設写真のみ。代替テキスト、出典、撮影日時を表示。未登録・読込失敗でも利用できる。写真がない施設を掲載禁止にしない |
| FR-11 | 外部経路案内 | 目的地座標を安全にURLエンコードしてGoogle Mapsへ遷移。LeSpotが取得した現在地をリンクの出発地へ自動付加しない。外部サービスへ移動することを示す |
| FR-12 | 情報の信頼性 | 項目ごとの確認日時・出典・期限切れが分かる。公開日を確認日として使わない。休業・非公開化・画像取り下げを運用できる |
| FR-13 | 管理者による登録・編集 | スキーマ検証、根拠・権利検証、差分・プレビュー、公開、ロールバックが行える。一般公開の書き込みAPIは作らない |
| FR-14 | 例外状態 | 読込中、取得失敗、0件、地域未対応、一部データ未取得、画像失敗、位置精度不足、非公開スポットを区別して次の操作を示す |
| FR-15 | 地域拡張 | 地域・カテゴリ・設備を設定とマスタで扱う。画面コードに名古屋だけの分岐を作らない。範囲外を「スポット不存在」と断定しない |
| FR-16 | 利用案内 | サービスの限界、地図・データ・写真出典、位置情報・外部送信、連絡先、利用条件を閲覧できる |

## 6. 検索条件の補足

座席は椅子・ベンチ・ソファ。設備はトイレ、電源、Wi-Fi、冷房、暖房、飲食可否、喫煙所、仮眠許可、横臥許可を扱う。喫煙所があることと休憩席で喫煙できることは別。飲食は持込可否等の条件を併記する。

料金の単純な「○円〜」を上限予算への一致根拠にしない。深夜は営業時間の対象日を画面に明示する。静かさは運営の観察時点の主観評価であり、測定値・保証・口コミ平均ではない。

## 8. データと運営責任

施設公式、名古屋市等の明示ライセンス付き公開データ、運営者の現地確認を優先する。公開データにベンチ・電源が載っていない場合は不明のままとする。根拠の確認は運営者、公開判断はプロダクトオーナーまたは委任された管理者が行う。AIによる文案生成だけでは確認完了にならない。

初期目標は60件、無料20件以上、屋内20件以上、権利確認済み写真付き40件以上。3プリセットそれぞれから直線750m以内に10件以上、うち無料3件以上を目指す。重複地域の同一スポットは全体件数で二重計上しない。カテゴリを満たすために実在しない情報を補わない。写真数等の目標変更は決定ログへ記録する。

公開時は全件の名称・位置・休憩利用条件が30日以内に確認済み。料金・営業時間は80%以上が確認済みを目標とし、残りは不明を明示する。現地・公式情報の確認計画、誤情報・権利申し立て対応は `DATA_OPERATIONS.md`。

## 9. MVPの検証と成功基準

### 機能・品質ゲート

FR-01〜16の受け入れテストを完了し、NFRの計測・レビュー記録を残す。重大障害0件、権利不明画像0件、秘密情報・GPSログ漏洩0件、非公開データ露出0件。未実施の実機・現地項目を免除した扱いにしない。

### ユーザビリティ仮説

対象に近い5名に「無料で座る」「屋内で電源を使う」「現在地を許可せず探す」の3課題を実施。計15試行中12以上が支援なしで候補選定と経路リンク到達まで完了、成功試行の中央値60秒以内、5名中4名以上が利用条件を理解できることを暫定合格とする。小標本のため市場適合性の証明とはしない。

### 公開後30日の確認

運営者が20件を再点検し、誤った肯定情報は1件以下を目標とする。誤りがあれば即時訂正し、件数だけでなく原因を分析する。運営工数・費用・問い合わせ内容を記録する。解析SDKをMVPの前提にせず、同意済み試験と手動集計から検証する。継続率等は測定していなければ不明とする。

## 10. 変更管理

詳細な技術・管理方式・費用上限・公開目標は暫定推奨であり、`DECISIONS.md` に承認待ちを残す。将来機能を追加する際は、認証、個人情報、投稿審査、画像保管、API課金の影響を再評価し、MVPの終了条件を無断で拡大しない。
